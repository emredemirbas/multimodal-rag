# Explicit local visual probe

Date: 2026-10-26

This is the first **stateless MP4/frame/OCR component**, not video upload in the
application. It creates no project/source/job, stores no application objects and
publishes no retrieval/citation evidence. Existing SRT/VTT/WAV paths are unchanged.
No paid/cloud provider, arbitrary URL/video downloader or vision-description model.

## Build and exercise authored cards

```bash
docker compose build visual-inspect
docker compose --profile visual-tools run --rm -T --no-deps --entrypoint python \
  visual-inspect -m app.vision.selftest
```

Build explicitly installs local FFmpeg/Tesseract and Debian English/Turkish OCR
language packages. No Ollama/Whisper weights are downloaded and no model/setup
request happens at inference time. The minimal image contains only the visual
tool, its shared kernel filter and pinned Pydantic, not API/database/S3/Celery code.
Normal startup excludes this profile. Use `run` as shown, not `up`, and do not add
`visual-tools` to ordinary application profiles. The command exits when finished.

The self-test generates its own fixed high-contrast English/Turkish card video
inside the disposable tool container. It checks inherited socket denial, actual
PTS, PNG generation, exact duplicate removal and explicit `en`/`tr` recognition.
Its combined-language diagnostic is reported separately: `en+tr` missed the
Turkish exact terms in the initial native test. Explicit-language success is not
reclassified as universal multilingual accuracy; no representative benchmark or
scene/terminal/code-quality gate has passed.

## Process an owned/authorized file

```bash
docker compose --profile visual-tools run --rm -T --no-deps visual-inspect \
  --authorized-input --language tr < /absolute/path/to/owned-tutorial.mp4
```

Select `en` (default), `tr`, or experimental `en+tr`; language selection is explicit,
not automatic detection or fallback. The acknowledgement is the operator's rights
assertion, not independent license verification. Only bytes enter stdin: no host
directory, Docker socket, app credentials or application-data volumes are mounted.
**Your host input file is not deleted.** Temporary copies/intermediates are confined
to the container's bounded tmpfs, cleaned on completion/error, and destroyed with
the container. Frames/OCR are not exported by this command.

Supported initial subset:

- non-fragmented ISO MP4, <=100,000,000 bytes and 600 seconds;
- one H.264/avc1, 8-bit yuv420p video; 16–1920 x 16–1080, unrotated;
- constant 1–60 fps, zero-based video/container timeline;
- optional AAC audio is ignored, **not transcribed**; other tracks/codecs fail;
- at most 20 uniform candidates, one per five seconds on short clips;
- fit to 960x540 grayscale, actual decoded millisecond PTS, deterministic PNG;
- exact decoded-image deduplication only: no scene detector or perceptual grouping.

Unsupported/malformed input fails with a content-free error, not a downloader,
codec fallback, fake timestamp or partially published result. Recognized text is
literal untrusted input; it is never executed or interpreted as instructions.
OCR can miss code, punctuation and Turkish characters. Grayscale/downscaling and
uniform sampling can miss useful visual changes. Use permitted subtitles for the
normal product workflow while video ingestion is not connected.

## Output and isolation

The JSON summary includes input/frame SHA-256, video geometry/duration/frame rate,
requested/actual sampled times, candidate/unique/text-bearing counts and declared
engine/language-data profile. It does not print OCR text, pixels, host paths or
raw native errors. `quality_approval` always remains `not_established`; ordinary
`component-complete` means parsing finished, **not accurate OCR or indexed video**.
Treat hashes as content fingerprints; do not publish reports for private clips.

Uniform candidates use the source duration; image filenames are generated by
FFmpeg from copied decoded PTS under an explicit 1/1000 encoding time base. The
requested neighborhood is checked independently (at most one second ahead), even
for discarded duplicate frames. Actual timestamp/PNG hash is retained for each
kept frame. An intentionally narrow P5 parser validates decoded pixel bounds;
standard-library PNG encoding needs no second native image decoder.

The Compose tool has no network, published ports or credentials, runs UID/GID 1000,
uses a read-only root, 192 MiB tmpfs, 1 GiB memory/no extra swap, 2 CPUs, 32 PIDs,
no capabilities, no-new-privileges and no core dumps. A fail-closed inherited
kernel filter additionally denies new sockets/socket pairs/connect. Native parsing
refuses to start when this restriction is absent; it is never installed in the
API/ordinary worker. MOV demuxing is forced, only file/pipe protocols are allowed,
and external data references/absolute external tracks are disabled.

Each fresh FFprobe/FFmpeg/Tesseract child receives only an allowlisted environment,
10/11 CPU seconds, 1 GiB address-space bound, 2 MB per-file output bound, 32 open
files and a <=15-second wall deadline. The native pipeline has a 120-second budget;
timeouts kill only its newly created child process group. This may reject complex
but otherwise valid media rather than consuming unbounded local resources.
OCR is bounded to 16,000 characters/frame. Language-data SHA-256 and engine versions
participate in the processing profile; rebuilding with changed packages/data makes
drift explicit. There is no mutable runtime language/model installer.

This is not a hardened learner-code runner or a production security certification.
The dedicated authorized video queue, checkpoints/leases, tenant/project fences,
observable original retirement/cleanup and complete source/project object deletion
must be implemented before any product upload flag is introduced. The accepted
future one-hour original eligibility and retained selected-frame/OCR policy do
not create application storage in this stateless slice. Visual retrieval, frame
citations, scene-change recall and broader OCR review remain follow-up.

## Private service boundary

The stateless follow-up adds `python -m app.vision.server` and a worker-side
`LocalVisualClient`. Optional Compose `visual` uses the same minimal image but only
the internal `visual-private` network, no host port/app environment/mounts. It binds
8091 before inherited kernel denial and verifies a fresh child's denied socket
creation before health becomes ready. Current API, frontend and workers do not
join that network. It is not a public upload or authenticated application API.

The diagnostic above can also be run with `-m app.vision.http_selftest`. A parent
connects over container-local loopback to the actual filtered service child in
the disposable **no-network** tool container; no host port, app record or user file
is used. It checks authored Turkish card OCR/PNG transport and pinned-profile
rejection. Original explicit-language/mixed-language quality caveats still apply.

Private version-one protocol:

- `GET /health/ready?language=en|tr|en+tr` returns strict engine/language-data/policy
  identity with its recomputed profile hash; default language is `en`.
- `POST /extract?language=...` accepts only raw MP4 bytes, one Content-Length and
  `Content-Type: application/octet-stream`. Exactly one `X-Visual-Profile` and
  `X-Input-SHA256` must match the pinned identity and actual bytes. No credentials,
  application IDs, URLs, content encodings, transfer encoding or Expect headers.
- Response includes strict protocol/input/identity/video/candidate fields and at
  most 20 frames with actual PTS, base64 PNG, image SHA-256 and literal untrusted
  OCR. **This payload is private content, never a log or public summary.** Both
  sides check selection/timeline, image hashes/CRC/geometry/bounded decompression
  and exact duplicate pixels. At most 18,000,000 response bytes are accepted.
- The client requires `extract(content, expected_identity=pinned)`; a readiness
  check never silently replaces that pin. Only `http://visual:8091` or explicit
  loopback test ports are accepted; no proxy, redirect, automatic retry or fallback.
- Capacity is one extraction and four connections. Header/body reading has an
  absolute ten-second deadline, including trickling peers. Existing native limits
  and 120-second pipeline budget remain. Response writes have a five-second
  timeout; the client has a 145-second absolute socket deadline (three seconds
  for health, with separate two-second connection timeout). Errors expose fixed
  codes, not media/text/paths/raw parser details. Busy/unavailable is retryable by
  a future bounded job policy; invalid payload/profile is not silently repaired.

This is local private parsing isolation, not production HTTP hardening or tenant
authorization. It creates no usage rows or invented model costs. Fixed route,
status, candidate/frame counts, duration and elapsed time are logged without input
fingerprints. Future durable jobs must enforce actor/tenant/project scope and
persist identity/checkpoints, lease/expiry fences and independently confirmed
raw/derived deletion before a product video capability can be enabled.

## Private database checkpoints

Migration 0013 separately adds trusted-worker `VisualCheckpoints.begin/save/load`.
It is not included in the native image and is not exposed through the CLI, HTTP
parser or application upload API. No video source/job is registered automatically.
Only a pre-existing exact scoped video/visual claim can access it.

`begin` pins actual MP4 digest/bytes, initiating actor/rights and full processing
identity before inference. `save` accepts one complete verified result atomically;
`load` rechecks image/text/manifest integrity before returning private content.
At most 20 PNGs/12 MB image bytes/320,000 OCR characters are staged in PostgreSQL,
not a public evidence table or final object store. These permitted derived bytes
remain until source/project deletion or later adoption cleanup. Input originals
are never stored by this component.

Every operation checks tenant/project/source/job/generation, initiating membership,
token, wall-clock lease and eligibility ending one hour after job creation. A
retry never extends it; expiry is not physical cleanup. A saved result survives
lease recovery but no interrupted per-frame decoder can resume in this slice.
Source/project cascades remove all staged bytes/text. Logs/aggregate metrics expose
accepted counts and scoped operation IDs, not content/input fingerprints; no
tokens, model duration or paid usage is fabricated. Video registration/queue,
original retirement/confirmed cleanup and atomic object adoption still precede
product uploads or published visual citations.

## Retained-frame inspection continuation

ADRs 0022/0023 subsequently add the dedicated optional visual queue, private
authorized registration, one-hour raw eligibility/verified retirement, and a
separate `VisualGalleryRepository.enqueue` command for prepared derivatives.
The latter uses `tutorial.publish_visual` to adopt one PNG per delivery; only a
complete manifest is shown. It never reruns native OCR or recreates an original.
These internal commands are not public MP4 upload APIs.

For a retained source, **View selected frames** opens the authenticated
`/projects/{project_id}/sources/{source_id}/frames` page. It shows unreviewed literal
OCR, actual PTS, source/extraction/publication identity and bounded PNGs through a
no-store server-only proxy. An empty gallery does not expose partial staging.
Source/project deletion removes all originals, orphan/adopted images and rows.
This is still not an active search index, answer citation, original-video player,
scene detector or representative OCR-quality approval. See
`visual-gallery-plan.md` and `visual-gallery-validation.md` for the separately
reported actual native workflow, fixture process-loss and frontend results.

The `visual` Compose health command now uses the same private `LocalVisualClient`
protocol. Generic urllib's User-Agent is intentionally not part of that protocol;
do not broaden the header allowlist just to probe readiness. Normal startup still
excludes optional visual services and product MP4 upload remains closed.

## Retained OCR indexing continuation

ADR 0024 adds an internal `VisualIndexRepository.enqueue(tenant, project, source,
publication_job, actor, idempotency_key)` command for an existing complete gallery.
Call it only from a trusted authorized operator context with both scopes and the
original initiating actor. A new key requests a new index generation; replay of
the same key returns the same logical job. This is not an HTTP upload endpoint or
a reason to expose database/storage credentials to the browser/native service.

`tutorial.index_visual` runs on the ordinary ingestion queue using its configured
hash or approved optional local semantic mode. The native visual service is not
needed again. Saved embedding groups survive bounded retries and continuations;
only a complete generation becomes searchable. Blank OCR fails honestly. Changing
mode needs a new internal index command; public video reprocess remains closed.

The gallery reports the active OCR index generation/space separately from its
publication generation. Source cards warn when that space differs from current
search. Answers/evidence/history label unreviewed OCR and link the exact retained
frame at actual PTS, including zero; this is a point observation, not the duration
of code on screen. Text-only models do not see the pixels or hear audio. Original
extraction identity and earlier citations remain stable across reindexing, with
no extra native call or raw retention. Complete source/project deletion still
removes all private chunks, evidence, derived chat and PNGs. Public MP4 upload and
representative scene/technical OCR quality remain separate gates.

## Opt-in automatic private workflow

ADR 0025/migration 0017 allows trusted private `VideoRepository.register` callers
to set `auto_process=True`. Acceptance pins the configured embedding space; the
two success handoffs atomically create gallery/index jobs and outbox records in
the parent's transaction. Existing manual callers are unchanged. Do not use the
connection/continuation parameters as public commands; they exist only for these
fenced internal handoffs. Derivatives remain retryable by their original initiator
after raw deletion without another native call. Archive is not cancellation;
explicit cancel stops the current stage. See `video-workflow-plan.md` and
`video-workflow-validation.md`, plus the README's opt-in authored native smoke.
This still adds no product upload form, MP4 API or original-video player.

## Experimental public boundary (default off)

The later ADR 0026 connects that accepted workflow to a standalone authenticated
MP4 API and same-origin form behind `VIDEO_UPLOAD_ENABLED=false`. It does not
enable a player/audio/scene/description path or widen accepted inputs. Configure
`local-visual` explicitly and use the README's opt-in command; capability is not
readiness/quality. Rights, explicit OCR language and permitted-derivative retention
consent are required. The source list tracks raw expiry/retirement/deletion
independently of job completion, and supports authorized failed cleanup retry.
Browser delivery abort is not processing cancellation; preserve the unchanged
draft/key when acceptance is uncertain. See `video-upload-plan.md` and
`video-upload-validation.md` for the separately reported actual public native and
100 MB spooling probes. Earlier authored/combined-language quality limitations
remain unchanged; no representative code-OCR or scene recall is established.
